# v2.26 开发与审查交接

从main的572a47ec8a90d854d610c6d3de10f232c94870c7建立`codex/v226-lord-command-chain`。需求授权包括实现、完整回归、固定种子对照、PR、合并与既有GitHub Pages部署；最终SHA、CI和线上核验另列于交付记录，不能用本文件代替发布凭据。

审查顺序：[玩法与迁移规则](RULES_V226.md)、[验证记录](VALIDATION_V226.md)、[固定种子对照](BALANCE_V226.md)。v2.25及以前的交付记录保留原样。

- `lord-intentions.js`只负责确定性候选、接令前军务检查、依据事实投影军议与单次外交责任。不得在此伪造军事事实或推进核心随机流。
- `strategy-network.js`持有军议账本和交涉入口，在同步提交内先消费已付款交涉，再核对既有承诺与实际军事事实；预览和执行均检查最新预算。
- `army-system.js`沿用军令和真实军团推进，保存持久接受／拒绝回执。对自主军议只从本局存档查找，不接受调用方临时构造军议绕过调遣权限。
- `game.js`仅为外部行动接入已有消费收据去重；核心结构保持103。直接诏令和原有地图军令仍使用原入口。
- 新UI使用默认专注视图可见的本月军议摘要，详情放入“军略→诸侯方略”；停战风险要显式勾选，不将实现细节作为玩家任务。

关键回归是`lord-command-chain-regression.js`与`lord-command-persistence-regression.js`。后者覆盖消费中断、反复完整恢复、目标易主、第三方驻军停战风险、实际攻城与最后一月。`lord-command-balance.cjs`比较同预算三种处理方式，并保留拒令、早结束与失败样本；`browser-lord-command.cjs`通过真实导出／文件导入和可见按钮检查两种屏宽。

不允许以更换种子或提升军团数值掩盖拒绝出兵。后续若扩展多军团或多目标，应先补重复指挥、已有援军优先级、多个外交责任方、前后身份、历史裁剪和跨月恢复用例。当前每月一项军议的范围是有意限制，不能把局势传闻自动转换成军事战果。
