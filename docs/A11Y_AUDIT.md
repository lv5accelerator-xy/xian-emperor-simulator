本轮只记录问题，未修改样式、Tab顺序或弹窗行为。检查环境为本机Chrome、file://直接打开、1366×900和390×900；覆盖开局、普通局第一月、桌面御前手册弹窗。使用真实指针点击、原生Tab/Escape和浏览器Accessibility Tree，并人工查看两种宽度截图。结构化结果见[检查摘要](data/a11y-summary.json)，完整DOM记录及截图随交付证据保存。

## 问题清单

| 编号/优先级 | 现象与复现 | 影响与建议 |
| --- | --- | --- |
| A11Y-01 / P1 | 桌面打开“更多→说明”，初始焦点在modal-confirm；按Tab后依次到BODY、save-btn、month-report-btn、御前档案、舆图等背景控件，而弹窗仍打开 | role=dialog和aria-modal=true没有使背景失活。后续独立修复应在通用弹窗中约束Tab/Shift+Tab，并使背景不可聚焦；本轮只记录 |
| A11Y-02 / P2 | 同一复现中在背景“总览”获焦后按Escape，弹窗关闭，焦点仍留在imperial-command-btn，没有回到help-btn | game.js openModal/closeModal未保存和恢复调用控件；后续修复关闭时恢复合理焦点，并覆盖鼠标关闭/取消/确认 |
| A11Y-03 / P2，待精确复核 | 统计卡“勉强维持”等小字在截图中偏暗；styles.css的.stat-card small前景#7e6e59，截图邻近底色约#171e1a，估算约3.45:1 | 这是小字号信息，并非禁用控件；低于普通文本4.5:1参考值。渐变底色/不同状态仍需逐点验证，再由独立视觉改动提高可读性 |
| A11Y-04 / P3，待读屏评估 | 军议/联军整张说明卡的按钮名称含整段说明和示例圣旨 | 名称并不为空，但读屏可能冗长；应人工评估简明动作名与描述分离，不能仅为加aria-label覆盖有效文案 |

A11Y-01/02为实际键盘复现；A11Y-03是源码色值结合截图底色的近似候选，不是全站对比度认证。初次按透明层叠粗算出的白底候选未作为失败统计，因为页面使用多层渐变，不能将白底近似当作实际背景。禁用按钮灰化没有计为对比度缺陷。

参考[W3C模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)的焦点循环与关闭返回要求，以及[WCAG对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)的普通文本4.5:1、较大文本3:1口径。来源仅用于解释检查方法，不据此宣称通过无障碍认证。
