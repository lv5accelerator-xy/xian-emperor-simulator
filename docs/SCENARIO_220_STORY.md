## 同步保存与缺史

核心 schema103 的 story220 保存 entryTurn、真实裁决、实际支出、来源后续、兑现状态和正常结束标记。稳定凭据为 story220:<gameCreatedAt>:decision:<eventId> 与 story220:<gameCreatedAt>:echo:<echoId>，保存在核心 appliedReceipts 中。裁决效果、记录和标记在决策事件监听前完成；后续效果和凭据在同次核心保存中落盘。终月效果进入当前结算来源账本。

storyManaged 保留人物记忆与因果历史，禁止通用因果/旧事系统另排同一延迟收益。重复点击、读取、完整导入与提交不再发放。裁决记录丢失但凭据仍在时，节点跳过、选择保持未知；后续结果丢失而凭据仍在时，状态归为 unknown，不重复发放，也不叙述成成功或失败。无故事字段的旧档从当前月接入，不反推过去选择。

调度顺序：定向短局/同题 → 开场 → 原196固定事件 → 普通220主线 → 帝业/因果/随机。完整导入以传入信封里的短局身份判断，避免上一运行实例污染；deadline不足12的局不插主线。其他四个普通剧本不插主线；其当前人物显示仍统一经过人物查询层。

## 准备提示和低钱粮路径

奏报区显示当前幕、下一节点和准备提示；路线完整条件、当前缺项及历史默认折叠。交礼权、散旧臣的永久影响在选择前展示。第6月疏散和第11月保全在缺钱时改为缩减安置，降低安全收益、另损官心；第3月缓议、第9月交玺仍有不花钱但牺牲权威的选择。
