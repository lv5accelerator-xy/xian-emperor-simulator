# 月末预检与完整备份（v2.18，v2.19 补充）

v2.19 的具体推荐、结算对账与恢复差异见 [结算对账](SETTLEMENT_AUDIT.md)。

推荐先处理接近失败线的警戒、安全、威望或枯竭国库，再根据当前短局的实际目标补缺。普通战役继续参考已选季度御题。短局目标均有余量时，可以留下行动守成；推荐只给出方案与代价，不会自动施行。

点击“结束本月”会先打开预检。固定部分与实际结算共用 `monthly-safety.js`：国库用度 −1、余下行动转化的安全与泄密收益、财政短缺、民间稳定和警戒反馈。表格显示受 0–100 上限限制后的值，短局与季度御题同时显示固定部分完成后的预期变化。

泄密检验不在预检中抽取。概率使用结算前风险，按原规则计算；随机泄密、世界与军团回报、季度奖惩另行改变终值。目标绿灯只说明固定部分达标，不承诺获章。取消预检不改变存档、行动、钱粮或随机序列；确认前若核心局势或御题已变化，重新生成预检，再次确认后才结算。

## 备份行为

| 留档 | 时机与保留数量 |
| --- | --- |
| 月度自动留档 | 每月首次稳定的完整存档；保留最近三个，刷新或当月继续行动不会覆盖原留档 |
| 替换前留档 | 开新局、短局、同题或长卷，重开、导入或恢复前；保留最近一次，可恢复刚被替换的现局 |

稳定留档等待各系统完成保存。新旧剧本及全部便携系统使用同一份完整存档格式，涵盖核心、世界、军团、政议、人物记忆、随机进度、短局复盘和收藏。月度留档跨局保留最近三个；同一月份不是逐操作撤销，旧局首次安装本版时从当时可用的存档留档，不能重建之前的月份。

开局、御前工具及终局的“存档备份”可查看并选择恢复。确认后先备份现局，再恢复全部已知系统；包中没有的系统键清除，避免混入另一局的数据。事务期间及重新加载前拦截旧延迟保存，成功后重新加载并点击“继续御览”。写入失败会尝试回滚，留档失败会阻止覆盖现局并提示检查存储或导出。

备份索引使用 `xian_emperor_save_backups_v2180`，最多三份月度快照加一份替换前快照。索引不放进自身快照或普通完整导出，避免递归膨胀；普通导出保存当时的完整现局；v2.19 起也可在备份列表单独导出选中的完整留档。备份只在当前浏览器中保留，清理网站数据会删除；换设备先导出完整存档。完整包恢复与旧版核心文件导入兼容，但只有完整包能一起恢复其他系统。

## 验证

```bash
node tests/monthly-safety-regression.js
node tests/save-backups-regression.js
node tests/settlement-replay-regression.js
node tests/balance-regression.js
```

回归覆盖国库 25→24 的终月一分差、预检无消耗、局势变化时拦截旧确认、五类短局推荐、守成入口、三个留档上限、旧局首留、完整数据恢复、延迟保存阻断、缺失系统清理、写入失败回滚和相同随机进度的实际续玩。

手机最小检查：在“许都夜变”裁决一次奏报，打开月末预检再取消，确认月份、国库及行动未变；确认结束本月后，在“存档备份”恢复第 1 月，重新加载并继续御览，应回到第 1 月、奏报待决、行动 2。桌面浏览器和自动回归不能代替真实 iPhone 的触屏与存储验证。
